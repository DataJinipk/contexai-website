How Intelligent Systems Behave

Before you build anything, learn to characterise the problem. This course gives you the vocabulary that every later decision depends on: what an agent is, what makes an environment hard, and why the same technique succeeds in one setting and fails in another.

What you will be able to do

On successful completion, you will be able to:

  • Define an agent in terms of perception, action and environment.
  • Distinguish reflex, goal-based and utility-based agents.
  • Classify an environment by observability, determinism and dynamics.
  • Predict which problem characteristics make a technique unsuitable.
  • Explain what rationality means for an agent with limited resources.
  • Identify where a performance measure creates perverse incentives.
  • Describe three deployment domains and the failure mode characteristic of each.
  • Assess a proposed AI application for its most likely failure mode.
  • Implement a review that lists which of a proposal's likely failures still lack evidence, an owner and a date.
  • Identify the performance element, critic, learning element and problem generator in a described learning agent.
  • Diagnose which part of a learning agent is at fault when it stops improving or improves at the wrong thing.
  • Implement an epsilon-greedy choice that tries untried options first and explores at a set rate.
  • Label each step of a tool-using agent's trace as a percept or an action, and place the agent boundary.
  • Classify how another agent changes an environment along Module 2's axes, and name the failure it causes.
  • Implement a check that refuses a reply that answers another request, has failed or is too old.
  • Identify, from a problem description, the five properties that decide an approach.
  • Choose fixed rules, search, planning under uncertainty or learning for a described problem, and reject the others by a named property.
  • Implement an ordered rule that recommends an approach from a problem's properties, and says when none fits yet.
  • Characterise an unfamiliar problem by the five properties and the dynamic axis, recommend an approach by Module 7's rule, and reject the others by a named property.
  • State what a proposal still lacks before it is a plan: a measure when no approach fits, a replanning trigger when search or planning under uncertainty meets a dynamic world, and a complete check for each likely failure.
  • Implement a review that runs a proposal end to end, from its properties to its verdict and the list of what is still missing.

How it works

Every module is taught aloud, one line at a time, with a pause after each line so it lands before the next one arrives — and you can go back, skip or replay at any point. Each module ends with a coding exercise graded by automated tests: you pass when your code passes its tests.
