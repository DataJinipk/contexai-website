AI at Work: A Practical Introduction for Non-Programmers

What generative AI actually does, where it fails, and how to use it at work without being misled by it. No coding. You leave able to decide what may go into an AI tool, how to make its output checkable, and whether a given output is fit to use, needs revising, or should be thrown away.

What you will be able to do

On successful completion, you will be able to:

  • Explain how a language model produces text by predicting likely continuations.
  • Distinguish tasks where a generative model is reliable from tasks where it is not.
  • Describe hallucination, data leakage and overconfidence with a workplace example of each.
  • Classify a piece of work information by whether it may be entered into an AI tool.
  • Apply a task, context, constraints and format structure to a workplace prompt.
  • Use source-grounding so that every claim in an AI output can be checked.
  • Evaluate an AI-generated output against its sources using a verification checklist.
  • Justify a decision to use, revise or discard an AI output in proportion to its stakes.
  • Construct a reusable prompt template for a recurring work task that names the reader, an invented example and a checkable output format.
  • Plan a chain of smaller prompts for a multi-step work task, with a check between each step.
  • Critique a prompt that produced an unusable output and revise it to remove the cause.
  • Construct a summary prompt that makes the tool quote its source for every point, and verify each point against the original.
  • Extract names, dates and amounts from a document into a table in which every value is traced to its source line, with any arithmetic done outside the tool.
  • Evaluate an AI-drafted email built from checked data and justify a decision to use, revise or discard it.
  • Construct a tool scorecard for one team task in which data-terms, permission and control checks must pass before quality, fit and cost are compared.
  • Test two or more candidate tools on the same set of invented or public cases and record the results on a fixed checklist, with counts.
  • Calculate the full monthly cost of each tool from its price, the team's volume and the time spent checking, and justify a recommendation to adopt, trial or reject it.
  • Design a written workflow for one recurring task that states the reader, the data class, the approved tool with where its approval is recorded, the steps from input to a checked output, and an owner.
  • Check two or more outputs of the workflow's saved template on invented or public cases with the verification checklist, and record the results with counts and a use, revise or discard decision.
  • Calculate the time per run with and without the workflow, including checking, and set stop rules and a review trigger that follow from the results.
